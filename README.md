# claude-code-api

**Свой HTTP-API к Claude, который работает на подписке, а не на платном API-ключе.**

Гейтвей запускает настоящий `claude` CLI в headless-режиме и отдаёт его наружу
как обычный OpenAI- и Anthropic-совместимый эндпоинт. Всё, что уже умеет
говорить с OpenAI, начинает работать с вашей подпиской — достаточно поменять
`base_url`.

Собран под две конкретные задачи: **самодельные умные очки** (голос, картинка с
камеры, низкая задержка) и **автоматическая первая линия поддержки** (Telegram,
контекст диалога, эскалация на человека).

```
устройство/бот  ──HTTP/WS──▶  claude-code-api  ──stdin/stdout──▶  claude CLI  ──▶  Claude
                                    │
                              лимиты, очередь,
                              ключи, диалоги
```

* Zero dependencies — весь рантайм это Node 20+ и сам `claude`. `npm install` не ставит ничего.
* Один файл конфига, один `docker compose up`.
* 65 тестов, включая полный E2E-прогон через поддельный CLI.

---

## Прежде чем ставить

Гейтвей ходит в Claude под вашей подпиской. Это накладывает два ограничения,
про которые лучше знать заранее:

1. **Лимиты подписки общие.** У плана есть 5-часовое и недельное окна. Бот,
   который отвечает клиентам, ест то же окно, что и ваш личный Claude Code.
   Гейтвей это видит (CLI сообщает утилизацию) и по умолчанию отказывает в
   новых запросах на `USAGE_GUARD=0.98`, чтобы автоматика не выжрала окно
   целиком.
2. **Потребительские планы рассчитаны на личное использование.** Свои очки —
   это ровно оно. Публичная поддержка платящих клиентов — уже серая зона:
   сверьтесь с условиями Anthropic (Usage Policy / Consumer Terms) до запуска в
   прод, потому что штатный путь для продукта — платный API. Технически
   гейтвей поддерживает оба: положите `ANTHROPIC_API_KEY` в `.env`, и `claude`
   пойдёт через API вместо подписки, ничего больше менять не надо.

## Быстрый старт

### 1. Поставить

```bash
curl -fsSL https://raw.githubusercontent.com/effectnebula15-indi/Claude-Code-API/main/install.sh | bash
```

Скрипт склонирует репозиторий в `~/claude-code-api`, сгенерирует `.env` со
свежими API-ключами и объяснит следующий шаг. Существующий `.env` он не трогает.

Вручную:

```bash
git clone https://github.com/effectnebula15-indi/Claude-Code-API.git
cd Claude-Code-API
cp .env.example .env
```

### 2. Подключить подписку

`claude` авторизуется один раз и живёт с долгоживущим токеном:

```bash
./scripts/login.sh          # запустит claude setup-token и запишет токен в .env
```

Или руками, на любой машине, где вы уже пользуетесь Claude Code:

```bash
claude setup-token          # откроет вход в браузере, выведет sk-ant-oat01-...
```

и положите результат в `.env`:

```ini
CLAUDE_CODE_OAUTH_TOKEN=sk-ant-oat01-...
```

> Альтернатива: смонтировать в контейнер уже залогиненный `~/.claude`
> (`-v ~/.claude:/home/node/.claude`). Токен надёжнее — он переживает
> пересборку образа и не тянет за собой ваши локальные настройки.

### 3. Запустить

```bash
docker compose up -d
docker compose logs -f
```

### 4. Проверить

```bash
curl http://127.0.0.1:8787/v1/ask \
  -H "Authorization: Bearer $(grep -oP '(?<=^API_KEYS=glasses:)[^,]+' .env)" \
  -H 'Content-Type: application/json' \
  -d '{"prompt":"Скажи привет одним предложением"}'
```

```json
{ "text": "Привет! Рад помочь.", "agent": "default", "model": "claude-sonnet-5", "ms": 1840 }
```

```bash

#   DOMAIN=api.example.com
#   ACME_EMAIL=you@example.com
docker compose -f docker-compose.yml -f docker-compose.tls.yml up -d
```

Caddy сам получит и будет продлевать сертификат. Порт гейтвея при этом

## Без Docker

```bash
npm i -g @anthropic-ai/claude-code   # сам CLI
node src/server.js                   # гейтвей, зависимостей нет
```

Для systemd есть готовый юнит: `deploy/claude-code-api.service` (с хардингом —
`ProtectSystem=strict`, `NoNewPrivileges`, ограничение путей на запись).

## Что торчит наружу

| Метод | Путь | Зачем |
|---|---|---|
| `POST` | `/v1/chat/completions` | OpenAI-совместимо. Стриминг через SSE. |
| `POST` | `/v1/messages` | Anthropic-совместимо, для официальных SDK. |
| `POST` | `/v1/ask` | Простое «вопрос → ответ». Для устройств и ботов. |
| `WS` | `/v1/ws` | Долгоживущий сокет: стрим по предложениям, отмена. |
| `GET` | `/v1/models` · `/v1/agents` | Список агентов и моделей. |
| `GET` | `/v1/usage` | Сколько окна подписки уже съедено. |
| `DELETE` | `/v1/sessions/{id}` | Сбросить диалог. |
| `GET` | `/healthz` · `/readyz` · `/metrics` | Мониторинг, Prometheus. |

Полное описание форматов — в [docs/API.md](docs/API.md).

### Любой OpenAI-клиент

```python
from openai import OpenAI

client = OpenAI(base_url="http://127.0.0.1:8787/v1", api_key="cca_ваш_ключ")

answer = client.chat.completions.create(
    model="glasses",                       # имя агента вместо имени модели
    messages=[{"role": "user", "content": "Далеко ли до Луны?"}],
)
print(answer.choices[0].message.content)
```

Так же заводятся Open WebUI, LibreChat, n8n, Home Assistant, Cursor и всё
остальное, что умеет «OpenAI-compatible endpoint».

## Диалоги: два режима

**Без состояния** (по умолчанию). Клиент шлёт всю историю каждый раз, как
принято у OpenAI. Работает с любым софтом, но история пересылается целиком.

**С состоянием.** Клиент передаёт `conversation_id` — заголовком
`X-Conversation-Id`, полем в теле или `?conversation=` для WebSocket. Тогда:

* историю помнит сам Claude, по сети едет только новая реплика;
* процесс CLI остаётся тёплым, ответ приходит без затрат на старт;
* работает кеш промпта, то есть окно подписки тратится заметно медленнее.

Для очков и для поддержки нужен второй режим — это и есть главный способ
уложиться в лимиты.

Соответствие «id диалога → сессия Claude» лежит на диске, так что перезапуск
гейтвея не теряет контекст: следующий запрос просто делает `--resume`.

## Агенты

Агент — это именованный профиль: свой системный промпт, модель, политика
инструментов, лимит длины ответа. Живут в `config/agents.json`, правятся без
пересборки образа.

В комплекте:

| Агент | Для чего |
|---|---|
| `default` | Обычный ассистент. |
| `glasses` | Короткие ответы под синтез речи: без markdown, максимум две фразы, числа словами. |
| `vpn-support` | Первая линия поддержки VPN. Промпт — в `config/prompts/vpn-support.md`. |
| `vpn-triage` | Классификатор входящих обращений, отдаёт JSON. Работает на `haiku`. |

```json
{
  "glasses": {
    "description": "Голосовой ассистент очков",
    "model": "sonnet",
    "system_prompt": "Ты голосовой ассистент умных очков…",
    "max_reply_chars": 700,
    "allow_images": true,
    "prewarm": 1
  }
}
```

`prewarm: 1` держит один процесс CLI прогретым — первый вопрос отвечается без
секунды-двух на запуск. Для очков это заметно.

**Инструменты по умолчанию выключены полностью** (`--tools ""`): агент не
получает ни shell, ни файлы, ни сеть. Это осознанно — гейтвей, торчащий в
интернет, не должен раздавать шелл. Включается явно, по одному:

```json
{ "tools": ["Read", "WebSearch"], "add_dirs": ["/srv/knowledge-base"] }
```

## Умные очки

Клиенты лежат в [`examples/glasses/`](examples/glasses/):

* `ask_sse.py` — только стандартная библиотека, стрим по предложениям.
  Годится для Pi Zero.
* `ws_client.py` — WebSocket: одно соединение на всю сессию, отмена ответа,
  когда носитель заговорил снова.

Ключевое для носимого устройства — гейтвей режет ответ **на предложения** и
отдаёт их по мере готовности:

```
{"type":"sentence","text":"До Луны примерно триста восемьдесят тысяч километров."}
{"type":"sentence","text":"Свет проходит это расстояние чуть больше чем за секунду."}
{"type":"done","text":"…","ms":2100}
```

Синтез речи начинает говорить первую фразу, пока модель дописывает вторую.
Задержка «вопрос → первый звук» падает в разы.

Кадр с камеры — просто base64 в том же запросе:

```json
{ "prompt": "Что это?", "image": "data:image/jpeg;base64,/9j/4AAQ…", "conversation": "glasses-1" }
```

Подробнее: [`examples/glasses/README.md`](examples/glasses/README.md).

## Поддержка VPN-сервиса

В [`examples/vpn-support-bot/`](examples/vpn-support-bot/) — Telegram-бот на
одной стандартной библиотеке (никаких зависимостей на маленькой VPS):

* один диалог на чат, `/reset` чистит контекст;
* модель ставит маркер `[[ESCALATE]]`, бот вырезает его и зовёт человека;
* 429 от гейтвея превращается в вежливое «сейчас много обращений»;
* номера карт вырезаются из ответа регуляркой — на случай, если промпт
  не сработал.

Промпт поддержки — `config/prompts/vpn-support.md`. Заполните плейсхолдеры
`{{...}}` перед запуском: пока они на месте, модель считает эти сведения
неизвестными и зовёт человека, а не выдумывает цены.

## Держим лимиты подписки под контролем

Это главная причина, по которой гейтвей сложнее прокси в 50 строк.

| Механизм | Переменная | По умолчанию |
|---|---|---|
| Параллельных запросов к модели | `MAX_CONCURRENCY` | `2` |
| Длина очереди, дальше 503 | `QUEUE_MAX` | `64` |
| Лимит на ключ, запросов в минуту | `RATE_LIMIT_RPM` | `30` |
| Лимит на ключ, запросов в сутки | `RATE_LIMIT_DAILY` | без лимита |
| Стоп при заполнении 5-часового окна | `USAGE_GUARD` | `0.98` |
| Стоп при заполнении недельного окна | `USAGE_GUARD_WEEKLY` | `0.99` |
| Потолок на один ответ | `TURN_TIMEOUT_MS` | `300000` |

CLI сообщает реальную утилизацию окон, гейтвей её запоминает и отдаёт:

```bash
curl -H "Authorization: Bearer $KEY" http://127.0.0.1:8787/v1/usage
```

```json
{
  "plan": {
    "status": "allowed",
    "windows": {
      "five_hour": { "utilization": 0.31, "resets_at": "2026-09-09T21:00:00.000Z" },
      "seven_day": { "utilization": 0.44, "resets_at": "2026-09-13T00:00:00.000Z" }
    }
  },
  "gateway": { "inflight": 0, "queued": 0, "turns": 128, "sessions": { "alive": 2, "warm": 1 } }
}
```

Те же цифры есть в `/metrics` для Prometheus (`cca_subscription_utilization`),
так что можно повесить алерт на «окно кончается».

## Безопасность

Гейтвей раздаёт доступ к вашему аккаунту Claude. Что сделано и что нужно
сделать вам:

* **Ключи обязательны.** Без `API_KEYS` сервис не стартует. Сравнение
  константное по времени. `ALLOW_ANONYMOUS=1` существует, но громко ругается в
  лог.
* **Ключи с областью действия.** Через `API_KEYS_FILE` — свой лимит и список
  разрешённых агентов на каждый ключ:

  ```json
  { "keys": [
      { "name": "glasses", "key": "cca_…", "agents": ["glasses"], "rpm": 20 },
      { "name": "vpnbot",  "key": "cca_…", "agents": ["vpn-support"], "daily": 2000 }
  ] }
  ```
* **Инструменты выключены,** настройки хоста игнорируются (`--safe-mode`),
  MCP — только явно заданный.
* **Картинки только как `data:`-URL.** Гейтвей принципиально не ходит по
  чужим ссылкам — это закрытый SSRF.
* **Порт по умолчанию слушает `127.0.0.1`.** Наружу — только через TLS-прокси.
* **Промпты не пишутся в лог** (`LOG_PROMPTS=0`).
* Контейнер работает не от root, `.env` создаётся с правами `600`.

Чего гейтвей **не** делает: не фильтрует контент, не хранит переписку (кроме
транскриптов самого `claude` в его каталоге) и не аутентифицирует ваших
конечных пользователей — если ставите его перед клиентами, авторизация их
самих остаётся на вашем приложении.

## Настройки

Все переменные с комментариями — в [`.env.example`](.env.example). Часто нужные:

| Переменная | Смысл |
|---|---|
| `CLAUDE_CODE_OAUTH_TOKEN` | Токен подписки от `claude setup-token`. |
| `API_KEYS` / `API_KEYS_FILE` | Кто имеет право звать гейтвей. |
| `DEFAULT_AGENT`, `DEFAULT_MODEL` | Что отвечает, если агент не указан. |
| `MAX_CONCURRENCY` | Сколько запросов к модели одновременно. |
| `USAGE_GUARD` | Порог отказа по окну подписки. |
| `SESSION_IDLE_MS` | Сколько тёплый процесс живёт без дела. |
| `CONVERSATION_FROM_USER_FIELD` | Считать поле `user` из OpenAI за id диалога. |
| `PUBLIC_METRICS` | Отдавать `/metrics` без админского ключа. |

## Разработка

```bash
npm test              # 65 тестов: юниты + E2E через поддельный CLI
npm run typecheck     # TypeScript-проверка JSDoc-типов
npm run dev           # автоперезапуск
```

E2E-тесты гоняют настоящий сервер поверх `test/fake-claude.mjs` — он говорит на
том же stream-json протоколе, поэтому маршрутизация, стриминг, диалоги,
отмена и обработка ошибок проверяются, не тратя ни одного токена.

Устройство кода — в [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md).
Если что-то не работает — [docs/TROUBLESHOOTING.md](docs/TROUBLESHOOTING.md).
